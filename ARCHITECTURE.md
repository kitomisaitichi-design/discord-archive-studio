# Discord Archive Studio

`studio/reading.py` persists monotone read watermarks. Viewport dwell batches up to 50 marks; Library unread searches use one of 32 bounded immutable snapshots to keep remaining results stable. Count caches invalidate by channel generation and watermark. Native library reader tabs share marks; external ZIPs use separate scopes. `studio/searching.py` extracts known operators outside quoted literals into parameterized predicates. Autocomplete returns eight locally saved candidates; browser requests cancel on replacement or close. A deterministic SQLite predicate includes direct image links without re-indexing histories.

`studio/linked_images.py` checks explicit selections against saved messages, coalesces URLs and hashes bytes into the shared media directory. Its worker yields to text work and republishes related ZIPs with retained channel options. Downloads cap bytes/time, sniff image signatures, validate public destinations at every redirect, pin the resolved address and preserve TLS hostname verification. No cookies or Discord authorization are sent to image hosts. Reader cache schema 4 recognizes embedded linked-image assets. `studio/attention.py` combines existing failure states, update errors and bounded missing-file checks. Opening it never retries network work; its retry endpoint rejects blocked tasks.

`web/chat-buffer.js` provides bounded page caching with cancellation and keyed transcript reconciliation. Reader pages use stable chronological cursors; Library paging uses timestamp/ID cursors in both directions. Scroll containers warm adjacent local pages near their viewport. Up to 500 normal message rows and eight playing rows are retained; stale observers and detached players are released. Container geometry is read once per reconciliation and Library scroll work is coalesced per frame. `web/media-view.js` shares local image/audio/video rendering and decorates new message nodes with direct JPG/PNG/GIF URL previews. Four concurrent image loads, eight unique links per message, a bounded 500-URL session status map, near-viewport observers, fixed aspect-ratio frames and error/offline fallbacks avoid eager history/media retrieval. HTTP(S) image requests are browser-native with no referrer; the backend does not proxy arbitrary URLs. The image toggle is shared browser storage. `studio/local_media.py` serves MIME types and validated single byte ranges; canonical media streams from files. ZIP assets remain within their existing 100 MB total cap, with videos limited to 10 MB. `web/midi-player.js` parses bounded SMF 0/1 events and synthesizes notes/tempo/sustain locally with at most 32 voices. No soundfont or codec dependency is added.

`studio/updates.py` checks only this public GitHub repository's latest stable release, with saved default-on controls, a daily default, conditional requests, bounded downloads and failure backoff. Portable assets require the GitHub SHA-256 digest and an exact, private-path-excluding package manifest. Payload references are installation-relative so moving the portable folder does not invalidate a pending stage. A maintenance flag and worker-cycle lock let active work finish while preventing a subsequent claim. `studio/update_installer.py` runs from the staged runtime after the original process exits, journals replacement files and backups, and starts the updated service on the same port and library. The new worker is gated by the verified startup receipt. Failed startup restores the prior files and leaves a visible rollback receipt; the failed release is skipped on later automatic checks. Data/Exports are never replacement targets, and .updates is excluded from archive discovery. Source checkouts expose status/settings without replacing their checkout.

`studio/searching.py` supplies literal phrase and metadata predicates, progressive 500-row local metadata backfill and complete legacy fallback. Captured names resolve stable author IDs; filenames and type filters refer to the same attachment. Canonical text FTS and indexed timestamp/ID cursors remain authoritative. ZIP index version 3 includes playable local MIME types and applies the same filters to all page boundaries. `web/queue.js` previews insertion by moving waiting rows through vacant movable slots, preserving running positions; a ghost, placeholder, FLIP movement, edge-scroll frame loop and keyboard controls reflect the prospective order before a guarded backend commit. `web/sounds.js` deduplicates state transitions, throttles progress and stores mute; it synthesizes small cues only after audio is unlocked through user interaction.

`studio/emojis.py` records captured custom emoji IDs and name aliases while messages are saved. Its persistent registry shares download reservations with avatars and manual attachments, suppresses repeated/failed requests, reuses SHA-256 image bytes, and uses credential-free CDN PNG/GIF endpoints. Visible saved message IDs populate legacy references without fetching history and take priority over background IDs within the same shared cap. Embedded ZIP images also populate the shared cache. Code literals remain untouched; unavailable artwork gets a readable label. `web/emoji-cache.js` hydrates visible inline tokens and reactions without a transcript reload; `web/emoji-library.js` provides bounded search and explicit retries. ZIP publication fingerprints cached versions and groups asset-driven rebuilds. Standard Unicode emoji use local fonts; no new dependency or invented replacement artwork is used. Official format reference: https://github.com/discord/discord-api-docs/blob/main/developers/reference.mdx .

`studio/credentials.py` uses Windows DPAPI and CNG AES-GCM for the current user's desktop profiles. `Connection` serializes account acceptance, pins an account ID, and protects a newly refreshed session against an old request's authentication failure. Disk changes trigger a bounded scan; unchanged credentials do not trigger new account requests.

`studio/access.py` checks current membership and computes channel permission overwrites from current roles/member data. It lists user-accessible threads through search on an already accessible parent. Ordinary channel jobs skip thread discovery. It never calls an individual saved resource to test whether it still exists. Missing/denied resources quarantine work; permission changes after preflight remain a race.

`studio/store.py` stores one canonical row per message ID, higher-quality source priority, prior captured revisions, attachment object hashes, author snapshots, explicit person aliases, queue checkpoints, independent schedules and publication state. SQLite WAL provides transactional pages and an FTS5 text index. Message body text and native IDs are preserved. File hashes identify byte-identical imports; TXT identities are synthetic and separate.

`studio/runtime.py` runs one export worker. A frozen newest-ID boundary separates current history from arrivals during the run. Committed cursors survive restarts and cooldowns. Request pacing is shared with metadata readers. A global message budget counts across channels; due jobs coalesce without interrupting a sweep. Adaptive intervals are independently derived from each channel's saved seven-day sample.

Normal incremental jobs page forward with `after=<newest saved ID>`, including imported or partially exported history. No-change heads produce no message-page request. Recent-edit scans are opt-in and bounded; full-history scans require an explicit current-job option and never propagate into schedules/catch-ups. An uncached scheduled channel establishes a current-head baseline. Initial manual history exports page backward, and paused tasks preserve their original direction and cursor.

`studio/exporting.py` downloads only manually selected Discord attachments, without session authorization. A separate persistent media queue runs after text work, reserves at most 100 MB / 50 files, and caps video bytes at 10 MB. Content-Length and bounded streaming enforce unknown-size limits. Text paging never invokes media downloads. Downloaded bytes become shared hash objects; server ZIPs retain independent channel views, include only eligible saved objects, validate CRC, and replace atomically. Presentation options and channel generations identify no-op publications. A richer live record takes priority over a lossy old import.

`studio/importing.py` parses JSON, streams DCE HTML markup without running it, and keeps ID-less TXT separate. Studio ZIP media objects are restored only by their validated content hashes. Arbitrary ZIP paths are never extracted.

`studio/server.py` binds only to loopback, validates Host/Origin, protects UI APIs with a SameSite/HttpOnly session cookie, and separately scopes a paired browser connector. Server-sent events deliver state changes without busy frontend polling. Logs omit request paths/search text and credentials. `web/` uses vanilla JS/CSS and bounded result pages. `studio/window.py` operates only on a uniquely named standalone browser app window; embedded browser sessions keep layout controls local.

The portable runtime consists of CPython, its standard library and required native modules. There are no pip/npm runtime dependencies. Development-only unit tests, synthetic fixtures, benchmarks, backups, reference files and all private Data are excluded from the Portable ZIP.

`studio/zipreader.py` snapshots ZIPs under the publisher lock, then closes the source before parsing. SHA-256 names persistent SQLite/FTS indexes; file signatures avoid repeated hashing during a session. These indexes are separate from the canonical library and page in chronological order with stable per-channel sequence numbers. Original and normalized ZIP names are validated, archive HTML is parsed as data, and only bounded referenced assets are cached. Connections close explicitly before Windows replacement. Mixed-format parts share stable message IDs; JSON is preferred. New ZIPs retain native presentation JSON when no JSON format was selected.

`studio/avatars.py` manages captured user-ID/avatar-hash tasks, automatically queued for visible saved messages in Library and ZIP reader. Downloads use the existing credential-free CDN transport, validate raster signatures, cap each at 1 MB, and share reservations with manual attachment tasks. The worker yields to running or ready text tasks, uses committed batch rests, serializes images with attachments, and waits with timing variation. SHA-256 objects retain captured avatar versions; publication attaches only local references for channels whose saved options enable pictures. The documented CDN image shape is from https://github.com/discord/discord-api-docs/blob/main/developers/reference.mdx . No profile lookup or message-history request is added. Visible message IDs are resolved against the selected saved source; browser requests cannot supply CDN URLs. A bounded IntersectionObserver hydrates images in place, with pending-only polling and no transcript invalidation. ZIP fingerprints include cached avatar versions for picture-enabled views.

`studio/reader_library.py` reads the existing canonical SQLite/FTS tables directly. Per-channel cursor tuples reuse the chronological index, message pages remain bounded, and saved media/avatar lookups stay local. This path does not export, import, copy the archive database or parse ZIPs; a filtered ZIP view is independent of the full saved library. The reader catalogue leads with these native library entries.

Archive discovery covers the configured destination, app directory and seven ancestor folders with recursive subfolder traversal, capped at 5,000 folders and 1,000 archives. Inventory is cached for one minute and refreshed explicitly on request. Standalone Discord JSON, HTML, Markdown and TXT files are detected by bounded header signatures and wrapped only in a temporary ZIP when opened, reusing the existing read-only index builder. It skips private/runtime/recovery trees, junctions, installer ZIPs and online-only placeholders; normalized paths prevent duplicate catalogue rows. Existing ZIPs are opened in place and retain their content-addressed reader caches. `web/queue.js` permits pointer movement from row text/background while excluding interactive controls; the backend still validates the active-job lock before changing order.
